# Bizilytics Battle — local event server (v7: self-paced Round 1, score visibility, three Final Round problem sets)
## Run (Node 18+, no installs)
```
node server.js              # http://localhost:3000   (stop with Ctrl+C)
node test.js                # 108 API/security/persistence/workflow checks (starts temporary servers)
node test-reset.js          # 86 checks: content pack, round resets, event reset, content security, migration
node test-v7.js             # 98 checks for the v7 changes (self-paced Round 1 timing, score visibility, problem sets, assignment)
python3 ui-smoke-test.py    # optional browser tests; need `pip install playwright` + `playwright install chromium`
python3 ui-smoke-v7.py      # browser check of the v7 screens
```
- **First run** creates `storage/db.json` and prints the organizer username (`organizer`) and a random password **once** in the terminal. Log in, then change them under **Controls → Organizer account**. If the password is lost: stop the server, move `storage/db.json` aside only if you accept losing event data, or edit nothing and restore from a backup you know the password for (`node restore.js`). There is no email recovery.
- **Other devices:** same Wi-Fi/LAN, open `http://<organizer-computer-IP>:3000`. Allow Node through the OS firewall for private networks only. Traffic is plain HTTP on a trusted venue network; do not expose the port to the internet. `HOST=127.0.0.1 node server.js` limits access to this computer. `PORT`, `HOST`, `BZ_TTL_MS` are read from the environment (see `.env.example`).
- **Pages:** `/` is the live app (`live.html`). `index.html` now only redirects to `/` (the old offline tool and its legacy questions/cases were moved to `legacy_backup/`, which is never served).
## Backups & restore
Automatic backups go to `storage/backups/` at startup, every 10 minutes, before schema migration, credential change and Round 1 reset (latest 30 kept; each is re-read to verify it parses). Manual: **Controls → Create backup**. Restore: stop the server, run `node restore.js storage/backups/<file>.json` (validates the file and keeps the current DB as `db-before-restore-*.json`), start the server. Migration v1→v2 is automatic, keeps all data and makes a `pre-migration` backup first; rollback = restore that backup.
## What is implemented and tested
Server-side: organizer login (scrypt-hashed password), 8-hour session expiry, logout, 5-failure/15-minute lockout, password/username change with current-password check, one-time stream tickets (no tokens in URLs), organizer-only APIs, input limits, generic 500 errors, audit log without secrets. Teams: self-registration with institution declaration → **pending**; organizer approve/suspend/disqualify (reason required)/reset code/revoke sessions/archive/restore; global switches for registration and team login; codes are stable (changed only at registration or organizer reset). Round 1: sequential quiz (self-paced by default since v7; organizer-paced mode kept), organizer chooses fixed or seeded-random order (frozen at start), **server-clock deadlines**, pause/resume, reveal-on-command, optional negative marking, duplicate-proof scoring, live-question edit lock, reset with confirmation + backup. Scoreboard: participants see published, finalized rounds only; tie detection with configurable tie-break; manual adjustments need a reason and are audited; finalized rounds lock. Live updates via SSE with auto-reconnect and re-fetch.
## Event workflow (v5)
States: `not_started → r1_active → r1_completed → r2_active → r2_completed → r3_active → completed`. Organizer **Controls → Event** shows one button for the only valid next step; every request carries the state it was made from, so double-clicks or stale screens get a 409 instead of a duplicate transition. Complete/finish need confirmation. Round open/finalized flags can no longer be set directly (`/api/settings` rejects them).
- **R1 → R2:** Complete Round 1 (final scores lock) → pick qualifiers (ranked list, "select top N" helper, confirm) → assign a case, prep time (10–15 min) and optional presentation (0 or 2–3 min) → Start Round 2. Non-qualifiers keep their records and scores; they see "did not advance".
- **Round 2/3:** server-side prep timer, one presentation at a time with a server timer, judge score sheets (several judges; **mean** of judge totals; re-saving a judge's sheet replaces it, never adds). Default weights (configurable via `POST /api/rubric` until judging starts): R2 analytical 40 / clarity 30 / relevance 30; R3 creativity 25 / practicality 25 / data 25 / communication 15 / cross-questions 10. These weights are project defaults, not rulebook values; approve or change them before the event. R3 prep 5–10 min, 3-minute pitch.
- **Finish:** locks Round 3 and publishes standings. Standings = R1 + R2 + R3 totals; ties shown with the chosen tie-break (Round 3 → 2 → 1 → none).
- **Migration:** schema v3 is applied automatically on first start, after a `pre-migration-v2` backup. An existing database keeps all teams, scores, answers and settings; the event state is inferred from Round 1 (running → `r1_active`, ended/finalized → `r1_completed`, otherwise `not_started`).
- **Windows CMD:** `cd C:\path\to\site` then `node server.js`. Test: `node test.js`. Restore: `node restore.js storage\backups\<file>.json`.
## Content pack, resets (v6)
- **Content** lives server-side in `content/` and `lib/content.js` (never served; `/content/`, `/lib/`, `/legacy_backup/`, `/storage/` return 404). `lib/content.js` adapts the pack to the app schema and **refuses to start the server** if anything fails validation: 30 unique Round 1 questions with four options and an existing answer key; six cases `DD-01…DD-06`, each with its own dataset (JSON must equal its CSV), chart specs resolvable against that dataset, and every derived value recomputed from the source rows; three Round 3 problem sets (`R3-01` from the pack; `R3-02`/`R3-03` from the v7 files).
- **Routing:** Round 1 → `db.questions` (round 1); Round 2 → only the six cases; Round 3 → only the three problem sets `R3-01…R3-03`. Participants receive content only through `/api/state` for their own active round; the organizer guides, answer keys and chart-ready CSVs (which contain computed answers) are organizer-only or never sent.
- **Charts:** the app has no charting library, so Round 2 charts are rendered as dependency-free inline SVG from the manifest. Some manifest charts display *calculated* values that the case tasks ask teams to compute (e.g. DD-01 weekly sales, DD-02 cost per registration). **Controls → Event settings → "Show Round 2 charts that display calculated values"** hides those charts (default: shown, as supplied).
- **Resets (Controls → Resets):** each reset has two explicit scopes. *Workflow reset* clears timers, active question/presentation state and presented lists, and keeps saved scores/answers/judge sheets, teams, qualifiers and case assignments. *Competition reset* additionally deletes that round's saved scores/answers/judge sheets (type `RESET ROUND n`). *Reset Entire Event* (type `RESET EVENT`) returns the event to "Not started" (workflow) or also clears all scores (competition). Teams, codes, accounts, content, settings and the audit log are never deleted. Every reset writes a backup first, is audit-logged (organizer, scope, round, prior state, time, backup file), and is idempotent per `requestId` (duplicate clicks/retries are ignored).
- **Limits (by design):** a *completed* round is locked and cannot be reset individually (use Reset Entire Event). Round 1 cannot be started again while saved answers exist; use the competition scope.
- **Migration v4:** on first start the Round 1 bank is replaced only if Round 1 is idle and no answers exist; otherwise your data is left untouched and **Controls** shows an "Install replacement content" button, usable after a Round 1 competition reset. A `pre-migration-v3` backup is always written first.
## v7 changes
**1. Round 1 self-paced (default).** Controls → Event settings → *Round 1 pacing* (changeable only before Round 1 starts): **Self-paced** (new default) or **Organizer-paced** (the original flow, unchanged). In self-paced mode the organizer clicks *Start* once; each team presses **Begin Round 1**, answers, and moves on with **Next question** (or **Skip**; no going back). Each question keeps its server-side time limit, and a team may move on without answering only after the limit expires or by explicitly skipping. The server records each team's start time, finish time and total duration (pauses excluded; never taken from the browser). If the organizer ends or completes Round 1, teams still in progress are closed automatically with their duration. Timing is stored with the team record (survives refresh, logout and restart) and shown to the organizer in **Controls → Round 1 timing**, with a CSV download (`GET /api/r1/timing.csv`, organizer only). Organizer *Next* and *Reveal* are not applicable in self-paced mode (the server returns 409). New endpoints: `POST /api/r1/begin`, `POST /api/r1/advance` (both team-only and idempotent).
**2. Round 2 / Round 3 scores.** After the organizer completes a round, each team sees its own score on **My Team → Your round scores** (with the number of judges); teams that did not qualify see "did not take part". Scores stay hidden while the round is active and still follow the organizer's *Teams see own score* switch. Judge sheets with a blank or missing criterion are now rejected instead of silently counting as 0. Scores are the mean of judge totals; re-saving a judge's sheet replaces it; completed rounds are locked; teams cannot call any scoring endpoint.
**3. Final Round problem sets.** Three sets: `R3-01` CampusCart (supplied pack) plus `R3-02` ThriftLoop and `R3-03` TiffinTrail (`content/participant/final_round_extra_sets.json`, organizer guides in `content/organizer/final_round_extra_guides.json`). The two new sets were written for this update to match the structure and rulebook timing of the supplied scenario; **have the organizers review them (figures, difficulty, guides) before the event.** Finalists see the three titles and one-line summaries and choose one; the full problem appears only for the chosen set.
**4. Selection rules.** (1) An **organizer assignment** (Controls → Round 3 → *Problem set per team*) always overrides the team's own choice; the team can no longer change it. (2) Otherwise the **team's choice** is used (changeable until preparation starts). (3) A team with neither gets the **default set** (the *Default set* selector) when preparation starts. (4) Everything **locks when the preparation timer starts**; later assign/choose requests get 409. Clearing an assignment returns the team to its own choice. Every choice and assignment is audit-logged. Event reset clears the picks; workflow resets keep assignments and choices. New endpoints: `POST /api/round/choose` (team), `POST /api/stage/r3/assign` (organizer).
**Compatibility.** No schema bump; defaults are added on startup (`settings.r1Mode='self'`, `stage.r3.sets={}`) and existing teams, scores, answers and judge sheets are untouched. A Round 1 already running organizer-paced when you upgrade finishes in that mode. The existing test files were adapted only where they assumed organizer-paced Round 1 or a single Round 3 scenario.
## Not implemented / unresolved (be honest before the event)
- **Round 2/3 gaps:** no written-answer or draft submission by teams (so there is nothing temporary to reset beyond timers/presentation state), no editable case/scenario content in the UI (content lives in `content/`), single presenting team at a time with a simple done-list, no CSV export of judge sheets.
- **Question-bank editor UI** (filters, reorder, import/export, preview): not built. The API supports add/edit/delete/`enabled`/`order` (`POST/PUT/DELETE /api/questions`).
- **Question bank:** the 30 Insight Sprint questions come from `content/participant/question_bank.json` (answers/explanations in `content/organizer/…`). Current-affairs items, if any, still need organizer source verification.
- **Dedicated tie-breaker round/question workflow, automatic qualification thresholds, CSV export, CSRF cookies**: not built (auth uses a bearer token held in sessionStorage, so classic CSRF does not apply, but XSS would expose it; all user text is escaped).
- JSON-file storage (single process, atomic file replace) is used instead of SQLite; fine for one venue, not for multiple server processes. Team codes are stored in plain text so organizers can distribute them. Sessions are in memory (everyone re-logs in after a restart; data persists).
- Rate-limit counters and sessions are per server process. No HTTPS.
- Not tested: >2 simultaneous browsers, tablets/real phones, long-running (hours) sessions, keyboard-only/screen-reader audit.

## Before the live event
Change the organizer password; add/verify questions and mark answer keys; set negative marking and order; decide tie-break; run `node test.js`; rehearse with 2–3 real devices on the venue network; create a manual backup; note the server's IP address.
## Manual end-to-end checklist (organizer + 2 participant devices)
1. Organizer: start server, log in, change password; add/approve two teams (or let them register and approve). Participants log in with team name + code.
2. Controls → Start event. Start Round 1; participants answer; Pause/Resume; Reveal; Next; End. Complete Round 1 (confirm).
3. Select top teams → Confirm qualifiers. Participant devices show qualified/not advanced instantly.
4. Assign a case, set prep minutes, Start Round 2. Qualified device sees the case; Start prep timer; Start/End a presentation; save judge sheets (two judges); Complete Round 2.
5. Confirm finalists, assign scenario, Start Round 3, repeat timers/judging (add a cross-question note), Finish event.
6. Check Scoreboard on all devices, restart the server, log in again, confirm state/scores unchanged, create a manual backup.
